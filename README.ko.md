**동작을 먼저 설계하고, 프레임을 하나씩 그립니다. 모든 수정의 근거를 남기는 캐릭터 애니메이션 작업 흐름.**

## 구조에서 결과물까지

<p align="center"><img src="assets/readme/workflow.svg" width="100%" alt="포즈 설계, 개별 프레임 검토, PNG와 JSON 내보내기"></p>

1. **구조 설계** — 캐릭터, 동작, 소품을 확인합니다. 방향별 지지, 가림, 접촉을 설계한 뒤 부위 경계와 팔레트를 검토합니다.
2. **프레임 검토** — 구조 승인 후 핵심 포즈와 개별 전환 프레임을 생성합니다. 원본, RAW, 후보, 인접 프레임을 비교합니다.
3. **에셋 내보내기** — 현재 캐릭터 그룹을 사용자가 승인하면 프레임 좌표, 피벗, 시간 정보를 포함한 PNG와 JSON을 생성합니다. 엔진 연동은 별도 단계입니다.

| 기능 | 실제 동작 |
| --- | --- |
| 유효 버전 | manifest가 지정한 그룹만 표시합니다. 변경된 해시는 갱신해야 하며 이전 승인 스냅샷은 무효가 됩니다. |
| 비교 검토 | 구조·AI RAW·후보 3열, 인접 프레임, 공통 표시 크기, 배경 전환, 프레임 재생. |
| 픽셀 보호 | C 방식으로 동일 좌표의 정지 영역을 복원하고 차이 이미지와 보고서를 저장합니다. |
| 요청 관리 | 참조, 예산, 응답을 오프라인 패키지에 기록합니다. 복구 시 기존 작업을 조회하고 중복 실행권 획득을 차단합니다. |
| 무손실 아틀라스 | 현재 승인된 그룹을 PNG와 JSON으로 내보내고 프레임별 픽셀 복원을 검증합니다. |

**동작 설계, 시각 분석, 이미지 생성은 AI 호스트가 맡고 사용자가 승인합니다.** 이미지 서비스, 자동 미술 승인, 엔진 플러그인은 포함하지 않습니다.

## 빠른 시작

**Python 3.10+, Pillow, macOS 또는 Linux**가 필요합니다. 작업 잠금에 `fcntl`을 사용하므로 Windows 네이티브 실행은 지원하지 않습니다. 패키지 루트에서 실행하세요.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install Pillow
python3 scripts/build_demo.py ../sprite-agent-demo
```

브라우저에서 `../sprite-agent-demo/review/index.html`을 엽니다. 구조, 테스트 색상 블록, 프레임 플레이어와 의견 내보내기를 확인할 수 있습니다. 색상 블록은 UI 테스트용이며 생성 캐릭터가 아닙니다. 출력 폴더는 비어 있어야 하며 재실행 시 새 폴더를 지정합니다. API를 호출하지 않습니다.

## AI 어시스턴트에서 사용

폴더 전체를 `sprite-sheet-agent`로 설치하고 `SKILL.md`를 최상위에 둡니다. 소재와 결과는 별도 작업 폴더에 저장합니다.

- **Codex:** 설정된 스킬 폴더(예: `~/.codex/skills/sprite-sheet-agent/`)에 복사하고 다시 로드한 뒤 `$sprite-sheet-agent`로 호출합니다.
- **Claude Code:** `~/.claude/skills/sprite-sheet-agent/` 또는 프로젝트 스킬 폴더에 넣고 다시 로드한 뒤 `/sprite-sheet-agent`로 호출합니다.
- **기타:** [AGENT.md](AGENT.md), [SKILL.md](SKILL.md), [제작 규칙](references/production-method.md)을 읽도록 합니다.

실제 호스트 세션에서 설치 경로를 검증하지는 않았습니다. README만 전달하면 전체 규칙이 로드되지 않습니다. 호스트에는 파일 접근과 시각 기능이 필요하며, 생성 서비스는 별도로 선택합니다.

승인된 정면·측면·후면 이미지, 목표 크기, 동작 목록을 준비하세요. 비대칭 캐릭터는 반대쪽 측면도, 소품은 별도 기준 이미지가 필요합니다.

> 지정한 캐릭터 작업 폴더에서 sprite-sheet-agent를 사용하세요. 삼면도를 확인하고 네 방향 걷기, 앉기, 일어서기를 계획하세요. 동작 목록, 소품 기준, 컬러 구조를 먼저 제출하고 제 승인 후 개별 캐릭터 프레임을 생성하세요. 그룹마다 검토 페이지를 갱신하고 원본, RAW, 실패 버전을 보존하세요.

## A / B / C 선택

| 방식 | 모델 입력 | 출력 처리 |
| --- | --- | --- |
| A | 원본 + 편집 마스크 + 짧은 지시 | 모델 반환 이미지를 저장하고 시각 검토. |
| B | A 입력 + 현재 작업 JSON | 모델 반환 이미지를 저장하고 시각 검토. |
| C | B와 동일 | 별도 보호 마스크로 원본 픽셀을 복원한 후 연결부와 동작 검토. |

마스크를 지원하지 않으면 기능 축소를 기록합니다. JSON은 제약이며 실행 보장이 아닙니다. C는 동일 크기·동일 좌표의 정지 영역에만 적용합니다. 앉기, 회전, 달리기에서 이전 머리 위치를 강제로 고정하면 안 됩니다.

동일 원본과 모델 결과에 C 합성은 최대 두 버전입니다. 두 번째는 유효 alpha 경계를 바꿔야 합니다. 추가 이미지 생성 두 회를 뜻하지 않습니다. 생성 횟수와 비용은 별도로 확인합니다. 프레임당 총 세 회는 권장 기본값이며 기존 작업 한도가 우선합니다. 적합한 후보가 없으면 수정 대기로 남깁니다.
