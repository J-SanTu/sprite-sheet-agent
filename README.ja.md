## 構造から納品まで

<p align="center"><img src="assets/readme/workflow.svg" width="100%" alt="ポーズ設計、フレーム確認、PNGとJSONの書き出し"></p>

1. **構造を設計** — キャラクター、動作、道具を確認し、方向ごとの支持、遮蔽、接触を設計します。部位の境界とパレットも確認します。
2. **フレームを確認** — 構造の承認後、キーポーズ、独立した中間フレームの順に生成します。元資料、RAW、候補、隣接フレームを比較します。
3. **アセットを書き出し** — 現行キャラクターグループの人による承認後、フレーム矩形、基準点、時間情報を含むPNGとJSONを出力します。エンジンへの組み込みは別工程です。

| 機能 | 実際の動作 |
| --- | --- |
| 有効バージョン | manifestが指定したグループのみを表示。変更後はハッシュを更新し、古い承認は無効になります。 |
| 比較レビュー | 構造・AI RAW・候補の3列、隣接フレーム、共通表示サイズ、背景切替、コマ送り。 |
| ピクセル保護 | C方式で同一座標の静止領域を復元し、差分画像とレポートを保存。 |
| リクエスト管理 | オフラインパッケージに参照、予算、応答を記録。復旧時は元のジョブを照会し、重複した実行権取得を防止。 |
| アトラス出力 | 承認済み現行グループからPNGとJSONを生成し、各フレームのピクセル一致を検証。 |

**動作設計、視覚分析、画像生成はAIホストが担当し、承認はユーザーが行います。** 画像サービス、自動美術承認、ゲームエンジンプラグインは内蔵していません。

## クイックスタート

**Python 3.10+、Pillow、macOSまたはLinux**が必要です。タスクロックは`fcntl`を使用するため、Windowsでのネイティブ実行には対応していません。パッケージのルートで実行します。

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install Pillow
python3 scripts/build_demo.py ../sprite-agent-demo
```

ブラウザで `../sprite-agent-demo/review/index.html` を開きます。骨格、テスト用色ブロック、フレームプレーヤー、レビュー書き出しを確認できます。色ブロックはUIテスト用で、生成キャラクターではありません。出力先は空である必要があります。再実行時は新しいディレクトリを指定してください。API呼び出しはありません。

## AIアシスタントで使う

フォルダ全体を `sprite-sheet-agent` としてインストールし、`SKILL.md`を直下に置きます。素材と出力は別の作業ディレクトリに保存します。

- **Codex:** 設定済みのスキルディレクトリ（例：`~/.codex/skills/sprite-sheet-agent/`）に配置し、再読み込み後に `$sprite-sheet-agent` を呼び出します。
- **Claude Code:** `~/.claude/skills/sprite-sheet-agent/` またはプロジェクトのスキルディレクトリに配置し、再読み込み後に `/sprite-sheet-agent` を呼び出します。
- **その他:** [AGENT.md](AGENT.md)、[SKILL.md](SKILL.md)、[制作規則](references/production-method.md)を読ませます。

これらの導入方法は実際のホストセッションでは未検証です。READMEだけでは全規則は読み込まれません。ホストにはファイル操作と視覚機能が必要で、画像生成手段は別途選択します。

承認済みの正面・側面・背面資料、目標サイズ、動作リストを用意します。非対称キャラクターには反対側の資料、道具には独立した基準資料を追加します。

> sprite-sheet-agentを指定の作業ディレクトリで使ってください。三面図を確認し、四方向の歩行、着席、立ち上がりを計画してください。動作一覧、道具基準、色付き骨格を先に提出し、私の承認後に独立した人物フレームを生成してください。各グループのレビュー画面を更新し、元資料、RAW、失敗版を保存してください。

## A / B / Cの選択

| 方式 | モデル入力 | 出力処理 |
| --- | --- | --- |
| A | 元画像＋編集マスク＋短い指示 | モデル出力を保存して視覚確認。 |
| B | Aの入力＋現タスクのJSON | モデル出力を保存して視覚確認。 |
| C | Bと同じ | 別の保護マスクで元ピクセルを復元し、接合部と動作を確認。 |

マスク非対応サービスでは機能縮小を記録します。JSONは制約であり実行保証ではありません。Cは同サイズ・同座標の静止領域に限定します。着席、回転、走行で古い頭の位置を固定してはいけません。

同じ元画像とモデル出力に対してC合成は最大2版です。2版目は実効alpha境界を変更します。追加の画像生成2回という意味ではありません。生成回数と費用は別途確認し、1フレーム合計3回は推奨初期値にとどめ、既存の上限を優先します。不適格な候補を合格にせず、修正待ちとして残します。
